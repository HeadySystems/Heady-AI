# ADR-0029: WASM WebContainer Sandbox In-Browser Execution

- **Status:** Accepted (2026-06-16)
- **Deciders:** Eric Anthony Haywood

## Context

Agents are designed to generate, compile, and run previews of client-side widgets, utilities, and full-stack web applications. Executing this generated code inside a backend Cloud Run container or virtual machine exposes the origin servers to security threats (arbitrary execution exploits) and incurs high compute costs. Previews must be isolated, secure, and run instantly without consuming server resources.

## Decision

1. **Browser-Resident Sandbox (WASM)**: All code previews generated by Heady agents will execute strictly inside the user's browser using **WASM WebContainers** (StackBlitz WebContainer API).
2. **Zero Server Footprint**: No backend Cloud Run instances or edge workers are allocated for preview execution. The WebContainer boots a micro-operating system in the browser's WebAssembly execution thread.
3. **Egress Firewall allowlist**: All network requests originating from the WebContainer sandbox are restricted via an allowlist of subdomains, preventing data exfiltration.
4. **WebSocket Communication**: The terminal shell (`xterm.js`) and file synchronization between the agent loop (Durable Object) and the WebContainer are maintained via secure, authenticated WebSockets.

## Consequences

- (+) Guarantees absolute safety for the backend infrastructure (malicious agent code runs inside a sandboxed browser thread).
- (+) Serverless execution: Zero origin compute costs for serving code previews.
- (+) Low latency: Code compiles and boots in milliseconds directly on the client.
- (−) Limited to modern browsers supporting SharedArrayBuffer and WebAssembly features.
- (−) Network access is limited; the sandbox cannot bind to private backends without explicitly proxying requests.
