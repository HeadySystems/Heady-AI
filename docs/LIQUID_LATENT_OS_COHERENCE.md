# The Coherence Architecture — a Self-Aware, Globally-Consistent Liquid Latent OS

> **Status:** Design + working skeleton · **Date:** 2026-06-16 · **Owner:** Eric Anthony Haywood
> **Scope (read this first):** this is the **meta-coherence layer of the existing Heady-AI rebuild** —
> the OS's nervous system — not a greenfield tree. It hardens what's already scaffolded so the legacy
> Heady failure modes (sprawl, drift, fail-open, secret leaks, dim drift, projection lies) **cannot
> recur as the OS is built.** If you meant a fresh OS tree, redirect me.

## 1. The thesis — consistency is built, not policed

"No data/consistency issues globally; everything known by the system; changes propagate everywhere
automatically; the system is self-aware" is **not** achieved by a smart runtime that edits everything when
you change one thing. That is the legacy fantasy that produced 372 entries of drift. It is achieved by
**four mechanical properties**, each of which already has a home in this repo or is added here:

1. **One authority per concern** (single source of truth). Every fact lives in exactly one place —
   `facts.yaml` (golden values/decisions) and OpenAPI contracts (shapes). Nothing is restated as truth.
2. **Generation, not authorship.** Derived artifacts (types, Zod, routes, `mcp-tools.json`, README
   badges, CI matrices, projection shells) are **generated FROM** the authority and stamped
   `AUTOGENERATED`. A change to the authority regenerates them; CI fails if a regen produces a diff.
3. **A fail-closed gate on divergence.** Any place where two sources of truth could disagree is checked
   by a gate that **blocks the commit** on contradiction — the same fail-closed discipline as
   gate-then-embed (`heady-embed`) and the secret scan.
4. **A derived map that computes blast radius.** The system reads a machine-derived model of itself (the
   **System Map**) to answer "what depends on X" and "what must regenerate when X changes." That is what
   "self-aware" means here — concrete, derived, queryable; not magic.

**Propagation = SoT + generation + gate + blast-radius.** When `facts.embedding.dim` changes, the dim
isn't *edited* in 48 places by an AI; it lives in *one* place, the 48 dependents are *generated from* or
*checked against* it, and the gate + ripple tell CI exactly what to regenerate and review. Automatic,
because there was only ever one home.

## 2. Invariant #1 — DERIVE, never author

> **The map's edges and the facts come only from artifacts that are already ground truth.** No file gets
> a hand-written `governed-by: ADR-0015` tag; no one maintains a separate "wiring" document.

If a relationship can't be derived from something that already exists, the OS **doesn't model it yet.**
This is non-negotiable, because hand-authored metadata *is* the drift problem — it goes stale the moment
code moves. The System Map's sources, all pre-existing:

| Knowledge | Derived from (ground truth) |
|---|---|
| Facts / locked decisions | `facts.yaml` |
| Package graph | `packages/*/package.json` (`@heady/*` deps) |
| Contracts / shapes | OpenAPI specs → Kubb (`packages/contracts`) |
| Skills | `.agents/skills/*` + `.claude/skills/*` frontmatter |
| Decisions | `docs/adr/*` index |
| Transfer DAG | `tooling/decomposition/manifest.json` (`depends_on`) |
| Target packages | `.data/decomposition/repos-manifest.json` |
| Content invariants | `tooling/data-consistency/invariants.json` |
| Change detection | the Merkle index (`tooling/embed-corpus`) |

## 3. Invariant #2 — the gate fails on CONTRADICTION, not INCOMPLETENESS

This is what makes the gate survivable on a pre-launch rebuild where **24 of 31 target packages don't
exist yet.** A naïve "everything must be wired and documented" gate would emit hundreds of "not built
yet" findings, cry wolf, and get disabled — worse than no gate.

| Tier | Meaning | Effect | Example |
|---|---|---|---|
| **`error` — contradiction** | Two sources of truth **disagree** | **Blocks** (exit 2) | `facts` says 384, a migration says 1536; a skill imports dropped Qdrant; a doc says 384-dim, a migration says 1536 |
| **`info` — incompleteness** | Something is **declared but unbuilt** | **Reported, never blocks** | 24 planned packages absent; a package without a README |

Only contradictions block. Incompleteness is the normal state of a build in progress.

## 4. The systems, federated under the Coherence Kernel

The OS already had the rule layer. The Kernel adds the **structural layer** and federates everything
under one index — it does not reimplement the others.

```
                        ┌──────────────────────────────────────────────┐
                        │            COHERENCE KERNEL                    │
                        │  tooling/coherence  (the realization of        │
                        │  heady-knowledge-cartographer, build-time)     │
                        │                                                │
   facts.yaml ─────────▶│  ① build System Map  (derive nodes + edges)    │
   package.json ───────▶│         → .data/coherence/system-map.json      │
   .agents/.claude ────▶│  ② check  (CONTRADICTION-tiered)               │
   docs/adr ───────────▶│         → coherence-report.json  (exit 2 on    │
   decomposition ──────▶│            any error-tier finding)             │
   repos-manifest ─────▶│  ③ ripple (blast radius of a change)           │
                        │                                                │
                        │  federates as SUB-GATES (invokes, not reimpl): │
                        │   • data-consistency  (content invariants)     │
                        │   • skill-registry    (store sync)             │
                        │   • embed-corpus Merkle (change detection)     │
                        └───────────────┬────────────────────────────────┘
                                        │ enforced via
                 ┌──────────────────────┴───────────────────────┐
                 ▼                                               ▼
   .claude/hooks/heady-rules.mjs                    CI / pre-push gate
   (per-write: ESM, no-localhost, no-TODO,          (whole-repo coherence;
    φ-constants, Zod, brand header)                  blocks merge on contradiction)
```

**Existing systems it composes (already in the repo):**

- **`facts.yaml`** — golden record (single source of derived facts).
- **`tooling/data-consistency`** — content-invariant engine (`invariants.json`: EMBED-DIM-384, etc.),
  MAPE-K consistency loop. Invoked by the Kernel as a sub-gate via `--json`.
- **`tooling/embed-corpus`** — gate-then-embed + the **Merkle index** (change-detection substrate).
- **`tooling/skill-registry`** — syncs `.agents/skills` → `.claude/skills`.
- **`.claude/hooks/heady-rules.mjs`** — per-write enforcement of the `AGENTS.md` hard rules.
- **`packages/contracts`** — OpenAPI→Kubb generation (one shape authority).

**New this layer:** `tooling/coherence` — the System Map builder, the contradiction-tiered gate, and the
ripple engine.

## 5. The System Map — what the OS knows about itself

`node tooling/coherence/src/coherence.mjs map` → `.data/coherence/system-map.json`
(currently **241 nodes, 26 edges**, all derived). Node kinds: `fact`, `package`, `adr`, `skill`, `tool`,
`hook`, `transfer-group`. Edge relations: `depends_on` (package→package from `package.json`, group→group
from the decomposition DAG). This is the queryable self-model — the build-time realization of the
`heady-knowledge-cartographer` skill ("what exists, what connects to what, where the gaps are"), but
deterministic and CI-gated rather than agent-narrated.

## 6. The coherence gate — the checks (all derived, all real)

`node tooling/coherence/src/coherence.mjs check` (exit 2 on any contradiction):

| Check | Contradiction it catches | Source A vs Source B |
|---|---|---|
| `S1/S2/S3` | toolchain/version drift | `facts.yaml` vs root `package.json` (pnpm, node, name, version) |
| `S4` | package escapes locked npm scope | `facts.registries.npm_scope` vs each `package.json` name |
| `S5` | manifest claims a package that's absent | `repos-manifest` vs `packages/` (absent+unplanned → `info`) |
| `S6` | target name ≠ real package name | `decomposition` targets vs real `@heady/*` names |
| `S7` | skill stores out of sync | `.agents/skills` vs `.claude/skills` |

## 7. Ripple — automatic propagation, made concrete

`node tooling/coherence/src/coherence.mjs ripple embedding.dim`:

```
target : facts.embedding.dim (= 384)
why    : propagates to every artifact that derives from or restates it
blast  : 48 files across 4 packages  → [embedding, csl-engine, db, config]
         + ADR-0003 / 0015 / 0024, REBUILD_PLAN_V2, STEPWISE_BUILD_SPEC, 5 compendium files
```

This is "changes affect all appropriate places automatically": you never hand-edit 48 files. The dim has
**one home** (`facts.yaml`); the ripple tells CI the exact regen/review set; generation rewrites the
derived artifacts; the gate blocks merge if any drifted. Edit-one-propagate-everywhere falls out of
single-source-of-truth + derivation — no runtime intelligence required.

**Wiring the gate (fail-closed):**

```bash
# pre-push / CI — blocks merge on any contradiction (exit 2)
node tooling/coherence/src/coherence.mjs all

# answer "what breaks if I change X" before changing it
node tooling/coherence/src/coherence.mjs ripple <facts.key | pkg:@heady/x>
```

Add `coherence` to the CI `scan` stage (already a `facts.pipeline.required_checks` member) and to a
pre-push hook. Per-file rule enforcement stays in `heady-rules.mjs`; whole-repo structural coherence is
the Kernel.
